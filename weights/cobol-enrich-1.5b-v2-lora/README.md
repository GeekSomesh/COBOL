# cobol-enrich-1.5b-v2 (LoRA adapter)

A LoRA adapter for [Qwen/Qwen2.5-Coder-1.5B-Instruct](https://huggingface.co/Qwen/Qwen2.5-Coder-1.5B-Instruct). It writes the documentation half of a COBOL decision rule: a title, a one-sentence intent, business names for COBOL fields, and concept tags. It never produces logic. In the pipeline, operators, values, actions and source lines always come from the parser (`src/llm/enrich.py: merge`).

Second training round. Compared with the first adapter ([../cobol-enrich-1.5b-lora](../cobol-enrich-1.5b-lora/README.md)), the training data adds three domains (insurance claims, payroll, shipping; 9 templates, 54 programs), so it covers 21 templates instead of 12. Validation and test templates are unchanged and were never trained on.

| | |
|---|---|
| Base model | Qwen2.5-Coder-1.5B-Instruct (Apache-2.0) |
| Adapter | LoRA r=16, alpha=32, dropout 0.05, all attention and MLP projections (18.5M trainable parameters) |
| Training data | `data/finetune/train.jsonl`: 702 rules from 254 synthetic programs, 21 templates, train split only |
| Training | 2 epochs, lr 2e-4 cosine, effective batch 8, bf16, loss on the answer only; 26 minutes on an RTX 3050 6 GB laptop GPU (`train_log.json`) |
| Selection | on the validation split by mean of field-name accuracy, intent similarity and concept overlap; it beat an early-stopped run (0.5 epoch, lower validation loss) and the first adapter |
| Prompt | `src/llm/prompts.py`, prompt version p4, zero-shot |
| Licence | Apache-2.0 (base model licence); training data is synthetic and generated by this repository |
| Checksum | `adapter_model.safetensors.sha256` |

## Results (from `results/`, synthetic held-out templates, same prompt for every model)
| Split | Model | Field names (exact) | Intent similarity | s/program |
|---|---|---|---|---|
| Validation | this adapter | 0.639 | 0.828 | - |
| Validation | first adapter (12 templates) | 0.607 | 0.795 | - |
| Test (3 unseen templates) | this adapter | 0.590 | 0.839 | 3.05 |
| Test | first adapter | 0.542 | 0.818 | 3.18 |
| Test | same base, 3-shot prompt | 0.563 | 0.837 | 3.52 |
| Test | Qwen2.5-Coder-7B, 3-shot prompt | 0.632 | 0.856 | 11.38 |

With more varied training data, fine-tuning now beats prompting the same 1.5B base on unseen templates for field names (+2.7 points); intent similarity is about even. The prompted 7B remains the most accurate and is the default; this adapter is the fast option (about 3.7x faster than 7B) and the default fallback when 7B is not installed. Training loss still falls far below validation loss, so more diverse data should keep helping. See `docs/limitations.md`.

## Use
```bash
.venv-train/Scripts/python scripts/merge_adapter.py --adapter weights/cobol-enrich-1.5b-v2-lora --out models/cobol-enrich-1.5b-v2/merged
python scripts/serve_model.py --merged models/cobol-enrich-1.5b-v2/merged --name cobol-enrich:1.5b-v2
COBOL_LLM_MODEL=cobol-enrich:1.5b-v2 python scripts/serve.py
```
(`make weights serve-model` does the first two steps.) With Hugging Face PEFT directly: `PeftModel.from_pretrained(AutoModelForCausalLM.from_pretrained("Qwen/Qwen2.5-Coder-1.5B-Instruct"), "weights/cobol-enrich-1.5b-v2-lora")`.
